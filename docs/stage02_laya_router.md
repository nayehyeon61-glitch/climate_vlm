# Stage 02: Laya를 기후 전문가 선택 라우터로 시험

소유자 요청(2026-11-06): Laya(https://github.com/NandhaKishorM/laya)가 추가 모델로 쓸모가 있는지 시험하고, Laya 학습은
제공한 전처리 안내서(Laya_Climate_Data_Preprocessing_and_Training_KO)의 방식을 따른다.

가설: 같은 물리 요약을 받았을 때, 기후 과제로 학습한 Laya가 고정 경로나 수치 MLP 라우터보다 예측 보정 전문가를 더 잘 고른다.

## 설정

- 기반 예측기: stage 01 학습 단계 2 checkpoint(`runs/stage01/stage2.pt`, 동결). 학습 단계 3은 검증 손실이 더 나빠서
  쓰지 않았습니다(0.527 대 0.512).
- 영역과 리드: 동아시아 28N–51N, 110E–143E(5.625°에서 4×6칸, 2.8125°에서 8×12칸, 하위 영역 NW/NE/SW/SE), lead 24 h.
- 기간(안내서 7절): A 2012–2015(전문가 학습), B 2016(라우터 학습), C 2019(확률 보정), D 2020(최종 시험). 각 창은 자기
  기간 안에 있고 양 끝에 24 h 여유를 둡니다. 결정 수는 B 1,448개, C 722개, D 724개입니다.
- 전문가 셋(`scripts/stage02_experts.py`, 분할 A에서 학습, 각 1,500 step):
  - baseline: 보정 없는 기반 예측.
  - advection: 850 hPa 온도 이류와 24 h 변화량을 입력으로 받는 보정 CNN.
  - moisture: 수분 수송과 수렴을 입력으로 받는 보정 CNN.
- 특징(안내서 4–6절, `scripts/stage02_dataset.py`):
  - 추론 때 쓸 수 있는 정보, 즉 D_μ로 다운스케일한 입력에서만 만듭니다. HR 정답은 쓰지 않습니다.
  - 진단량은 전 지구에서 물리 단위로 계산한 뒤 영역으로 자릅니다.
  - T850 이류, q850 수렴, z500 편차와 경도, z500과 T850의 24 h 변화를 영역 평균, 분위수, 강한 칸 비율, 하위 영역 4개로
    요약해 33개 특징을 만들고, 한 번만 반올림합니다. 평년값과 "강함" 문턱값은 학습 분할에서만 구합니다.
  - Laya 입력은 그 특징을 그대로 쓴 `state` 문장(약 282 토큰, 전체 입력 327–344 / 1024 토큰)입니다.
- 라벨: 영역에서 면적 가중 MSE를 분할 A의 시간 분산으로 나누고 다섯 변수(z500, t850, t2m, u10, v10)로 평균한 E가 가장 작은
  전문가(hard label). 상위 두 전문가 차이가 5 % 미만이면 near tie로 따로 기록합니다.
- 라우터(`scripts/stage02_router.py`):
  - A: 고정 경로(baseline, advection, moisture, 분할 B에서 가장 좋은 고정 전문가)와 oracle.
  - B: 같은 33개 특징을 받는 MLP(은닉 64, 6,915 파라미터).
  - C0: Laya 기본 checkpoint(laya-multilingual) zero-shot.
  - C1: Laya를 분할 B로 미세조정(인코더 동결, soft-ce, 8 epoch, 184 update).
  - C2: 동결 Laya의 선택지 상태 위에 작은 head만 학습.
  - 모든 라우터의 온도는 분할 C에서 맞추고, 분할 D에서 정확도, Brier, NLL, ECE와 라우팅한 장의 RMSE/ACC를 봅니다. 신뢰구간은
    7일 블록 bootstrap입니다.

## 해석

- 전문가 자체는 효과가 큽니다. 두 보정 전문가 모두 baseline보다 E를 절반 아래로 줄이고(0.408에서 0.173), z500 RMSE를
  157 m²/s² 줄입니다(신뢰구간 −183 ~ −131).
- 그러나 라우팅으로 얻을 수 있는 몫이 작습니다. 완벽한 oracle도 항상 advection을 고르는 것보다 E가 7 %만 낮습니다
  (0.161 대 0.173). 분할 D 결정의 18 %는 상위 두 전문가 차이가 5 % 미만인 near tie입니다.
- Laya zero-shot은 쓸 수 없습니다. 모든 결정에서 baseline을 골라 정확도가 0.022입니다.
- 미세조정한 Laya와 Laya 상태 위의 head는 둘 다 다수 클래스(advection)로 붕괴했습니다. 분할 C 정확도는 0.015에서 0.548로
  올랐지만, 그것은 항상 advection을 고른 정확도와 같습니다. 확률은 잘 보정되어(ECE 0.035) soft 혼합에서는 z500 RMSE가
  327.8에서 325.2로 조금 낮아지지만, 결정으로서는 아무것도 구분하지 못했습니다.
- MLP도 다수 클래스를 이기지 못했습니다(정확도 0.575 대 0.613, E 0.1766 대 0.1730). 같은 특징으로 수치 라우터도 못 한다는
  것은 문제의 원인이 Laya보다 특징과 라벨 쪽에 있다는 뜻입니다.
- 라벨이 바람 오차에 끌려갑니다. baseline의 E 가운데 u10과 v10이 약 87 %를 차지하고, E 라벨과 단일 변수 라벨의 일치율은
  u10/v10이 0.70–0.75, z500/t850/t2m은 0.47–0.58입니다. u10과 v10은 stage 01 모델에서 입력에 없는 출력 전용 채널이라 기반
  예측이 기후값에 가깝습니다(stage 01 해석 참고). 그래서 라벨이 "어느 전문가가 바람 평균장을 더 잘 고치나"에 가깝고,
  특징(이류, 수렴, z500)이 그것을 설명하기 어렵습니다.

결론: 이 설정에서 Laya는 추가 모델로 이득이 없습니다. zero-shot은 쓸 수 없고, 미세조정해도 다수 클래스를 넘지 못하며, 같은
일을 하는 MLP보다 약 20만 배 느립니다. 다만 이 결론은 Laya의 한계라기보다 이 과제의 한계일 가능성이 큽니다. 다시 시험한다면
다음을 먼저 바꿔야 합니다.

1. 라벨: 변수별 라벨 또는 바람을 뺀 E로 바꿔 바람 오차가 라벨을 지배하지 않게 합니다.
2. 전문가: 서로 다른 상황에서 이기는 전문가(예: 리드별, 계절별, 대류와 종관 상황)를 두어 oracle 이득을 키웁니다.
3. 기반 예측기: GPU에서 더 학습한 stage 01 모델 위에서 시험합니다. 지금 기반 예측기는 persistence 수준이라 전문가 보정이
   대부분의 일을 합니다.
4. Laya: 인코더를 동결하지 않고 학습하거나, 숫자를 문장으로 쓰는 대신 수치 특징을 직접 넣는 방식을 비교합니다.

## 재현

```bash
pip install -e <laya clone>          # laya-multilingual checkpoint는 HF_HOME의 Hugging Face 캐시
bash scripts/run_stage02.sh          # 예측, 전문가, 데이터셋, Laya dry-run/예측/미세조정, 라우터 비교
FROM=router bash scripts/run_stage02.sh   # 중간부터 다시: forecasts | experts | dataset | laya | router
```

CPU 4코어에서 걸린 시간은 예측 65분(IC 5,808개, IC당 약 0.67 s), 전문가 학습 7분, Laya 미세조정 87분, Laya 예측 분할당
3~7분입니다. 결과물은 `runs/stage02/`(저장소 밖)에 쓰고, 점수와 표는 `docs/stage02/`에 씁니다.
